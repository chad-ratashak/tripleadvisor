## 3. Game state model

- **`GameData`** (`GC/engine/data/GameData.java`, `implements Serializable, GameState`). Accessors: `getMap()` (territories, connections, routing), `getUnits()` (never shrinks — count live units by walking territories), `getPlayerList()`, `getResourceList()`, `getProductionFrontierList()`, `getProductionRuleList()`, `getTechnologyFrontier()`, `getSequence()` (L249), `getUnitTypeList()`, `getProperties()` (L297), `getHistory()` (L382), `getRelationshipTracker()` (L491), typed delegate getters (`getMoveDelegate`, `getBattleDelegate`, `getEndRoundDelegate`, …).
- **Locking.** `acquireReadLock()` (L454) / `acquireWriteLock()` (L470) return a closeable `Unlocker`; the class doc says code outside the engine must never take the write lock. The lock is a `ReentrantReadWriteLock` (no upgrade from read to write).
- **Mutation.** Only through `Change` objects: `GameData.performChange(Change)` (L572) takes the write lock and fires `GameDataEvent`s. `Change`/`CompositeChange` (`GC/engine/data/`), factories in `GC/engine/data/changefactory/ChangeFactory.java` (`changeOwner`, `addUnits`, `removeUnits`, `moveUnits`, `changeResourcesChange`, `attachmentPropertyChange`, …). Every `Change` has `invert()`, which is how the battle calculator rolls back (§5).
- **Live change feed.** In a running game every change is broadcast on `IGame.GAME_MODIFICATION_CHANNEL`; `GC/engine/framework/HistorySynchronizer.java:100-120` shows how to subscribe (`registerChannelSubscriber(listener, IGame.GAME_MODIFICATION_CHANNEL)`). With `LocalNoOpMessenger` delivery is synchronous.
- **History.** `GC/engine/history/{History,HistoryWriter,HistoryNode,Round,Step,Event,EventChild}.java`: a tree Root → Round → Step → Event → EventChild whose rendering data includes `MoveDescription`, `DiceRoll`, unit collections and territories. The existing log renderer `GC/triplea/ui/history/HistoryLog.java` is a `JDialog`; its preorder walk (L246-276, L313-330) is the recipe for a headless move log. `History.enableSeeking` + `gotoNode` replays the state to any node (used by `GC/engine/stats/StatisticsAggregator.java`).
- **Attachments** (`GC/triplea/attachments/*`) carry all map-specific rules; option names are resolved by a `switch` in each attachment class (no reflection), via `GameParser.setOptions` (`GC/engine/data/gameparser/GameParser.java:876-930`). DTD: `game-app/game-core/src/main/resources/games/strategy/engine/xml/game.dtd` (no XSD).

## 5. Cloning and the existing simulation substrate

- **Clone.** `GameDataUtils.cloneGameData(GameData, GameDataManager.Options)` (`GC/engine/framework/GameDataUtils.java:38`) is a full in-memory serialization round trip (no gzip). Also `gameDataToBytes`/`createGameDataFromBytes` (L52/62) and `translateIntoOtherGameData(T, GameData)` (L73; matches by name, units by UUID). Gotchas: default options drop delegates (then `getDelegate("move")` throws on the clone — use `Options.builder().withDelegates(true)`); hold **no lock or the write lock** while cloning (`saveGameUncompressed` takes the write lock itself at L158; holding only the read lock deadlocks). Cost is a whole-graph serialization; `ConcurrentBattleCalculator:106-130` halves its worker count when a copy takes >3 s and uses one worker past 20 s; `smoke-testing/build.gradle.kts` gives tests a 2 GB heap for this reason.
- **Battle calculator** (`GC/triplea/odds/calculator/`): each `BattleCalculator` worker deserialises its own clone (`Options.forBattleCalculator()`, L43), swaps in the given attackers/defenders, fights a **real `MustFightBattle`** headless (L110-111) through `DummyDelegateBridge`/`DummyPlayer`, records `BattleResults`, then undoes everything with `allChanges.invert()` (L121). It is therefore rules-faithful for one normal battle (support, first strike, AA, bombardment, Low Luck, territory effects) but does **not** cover scramble, air battles, bombing raids, rockets, or human-quality retreat/casualty choices (DummyPlayer retreats to an arbitrary allowed territory; casualties are engine defaults adjusted by order-of-loss or keep-one-land-unit).
- **ProAi's own lookahead** (`GC/triplea/ai/pro/AbstractProAi.java:156-272`): clones with delegates, wires `dataCopy.getMoveDelegate().setDelegateBridgeAndPlayer(new ProDummyDelegateBridge(...))`, steps through its remaining steps on the copy, runs **real `MoveDelegate.performMove`** on the copy, and resolves battles with `ProSimulateTurnUtils.simulateBattles` (`GC/triplea/ai/pro/simulate/ProSimulateTurnUtils.java:43-105`), which asks the odds calculator and then applies the *single closest-to-average* outcome as Changes. So the repo already contains the "simulate a turn on a copy" pattern, but its battle step is an average, not a sampled trajectory.
- **Delegates can run without a `ServerGame`:** set a bridge, `start()`, act, `end()` — `GC/triplea/delegate/WW2V3Year41Test.java:457-480` and `MoveDelegateTest.java:46-59` (both under `game-app/game-core/src/test/java/games/strategy/`).
- **Randomness.** `IRandomSource` (`GC/engine/random/`): `PlainRandomSource` (unseeded `SplittableRandom`, **no seed constructor**) is the `ServerGame` default; `CryptoRandomSource` for network games. `ServerGame.setRandomSource(IRandomSource)` (L721) is the injection point for a live game. Both calculator bridges (`DummyDelegateBridge`, `ProDummyDelegateBridge`) hard-code `new PlainRandomSource()`. There is **no `ScriptedRandomSource`**; tests script dice with `MockDelegateBridge.whenGetRandom(...)` (`game-app/game-core/src/test/java/games/strategy/triplea/delegate/MockDelegateBridge.java:57-79`, test scope only, not exported via testFixtures).

## 7. AI player architecture

- **`Player`** (`GC/engine/player/Player.java`) extends `IRemote`, 29 `@RemoteActionCode` methods: `start(String stepName)` plus all decision callbacks (`selectCasualties`, `retreatQuery`, `scrambleUnitsQuery`, `shouldBomberBomb`, `selectTerritoryForAirToLand`, `confirmMoveInFaceOfAa`, …). `PlayerBridge.getRemoteDelegate()` (`GC/engine/player/PlayerBridge.java:57`) returns the current step's delegate proxy; `getRemotePersistentDelegate("edit")` the edit delegate.
- **`AbstractAi`** (`GC/triplea/ai/AbstractAi.java`): `start` is **final** (L495-530) and dispatches on step-name suffix via `GameStep.isXxxStepName` (`GC/engine/data/GameStep.java:164-222`): `Bid`/`Purchase` → `purchase(boolean forBid, int pus, IPurchaseDelegate, GameData, GamePlayer)`, `Tech` → `tech`, `Move` → `move(boolean nonCombat, IMoveDelegate, GameData, GamePlayer)`, `Battle` → `battle(IBattleDelegate)`, `Politics` → `politicalActions()`, `Place` → `place(boolean, IAbstractPlaceDelegate, GameState, GamePlayer)`, `EndTurn` → `endTurn`. `UserActions` and `TechActivation` are never dispatched. The four abstract methods are `purchase`, `tech`, `move`, `place`; ~25 callbacks have sensible defaults (no retreat, default casualties, etc.).
- **Concrete AIs.** `ProAi` ("Hard") `GC/triplea/ai/pro/ProAi.java` with one static shared `ConcurrentBattleCalculator`; `FastAi` (`GC/triplea/ai/fast/FastAi.java`, ProAi logic with a dice-free `FastOddsEstimator`); `WeakAi` ("Easy"); `DoesNothingAi` and `FlowFieldAi` in `game-app/ai`.
- **ProAi internals worth reusing.** Orchestrator `AbstractProAi` (stores plans between phases); per-phase snapshot `ProData` (TUV map, win% thresholds 90/65 with dice, 95/75 Low Luck); `ProCombatMoveAi`, `ProNonCombatMoveAi`, `ProPurchaseAi` (purchase and place), `ProRetreatAi`, `ProScrambleAi`, `ProPoliticsAi`; candidate generation in `GC/triplea/ai/pro/data/ProTerritoryManager.java` (`populateAttackOptions` L81 → `findAttackOptions` L386; per-unit land candidates from `GameMap.getNeighborsByMovementCost` confirmed by `getRouteForUnit` + movement cost + blitz checks in `isLandMoveOption` L878; `populateEnemyAttackOptions` / `populateEnemyDefenseOptions` for threat maxima). These are **heuristic candidates, not validated** — the comment at L751-754 says `MoveValidator` still gates the real move. Moves are submitted by `ProMoveUtils.doMove(ProData, List<MoveDescription>, IMoveDelegate)` (`GC/triplea/ai/pro/util/ProMoveUtils.java:413-459`) → `performMove`. `ProBattleUtils.estimateStrengthDifference` is a near-free power heuristic; `ProOddsCalculator` (`GC/triplea/ai/pro/util/ProOddsCalculator.java`) is a thin wrapper (skips obvious cases, `runCount = max(16, 100 - minArmySize)`), not a cache. `ProData.initializeSimulation(proAi, data, player)` needs an `AbstractProAi` reference (**UNCERTAIN** whether a dummy suffices).

Italy (L3743-3758): +5 "Control the Mediterranean" (no enemy surface ships in sea zones 92-99); +5 "Roman Empire" (Axis-owned 3 of Greece, Egypt, **Southern France**, Gibraltar); +5 North Africa (Alexandria, Morocco, Algeria, Tunisia, Tobruk, Libya); +2 each Iraq / Persia / Northwest Persia. **No German or Italian objective mentions France.** France has no objectives. The USA gets +5 per turn for a land unit in France (`triggerAttachment_Americans_5_Presence_In_France`, L4350).

**France-capture triggers.** `conditionAttachment_French_1_Lose_France` (L3923-3925: Axis-allied ownership of France) fires `triggerAttachment_Germans_Conquer_France` (L4377-4384, `after:germansBattle`) or `triggerAttachment_Italians_Conquer_France` (L4385-4392, `after:italiansBattle`); each has `uses=1` and only flips the French liberation switch (L3926-3933) so the one-time "+4 infantry on liberation" triggers (L4401-4450) can later fire. **The Italian and German triggers have identical effects.** Balanced Mod additionally has Vichy rules (Southern France and colonies flip to Neutral_Axis unless an Axis power occupies Southern France; Italy or Germany gain a factory_minor + harbour there) and sets French `destroysPUs=true` *after* the first capture, so only the first capture plunders.

**What Italy actually gains by capturing France instead of Germany (engine-verified, §8).** The French PU bank at the moment of capture (19 PUs in round 1, since France collects income only at the end of its own, later turn), the territory's 4 PUs/turn, the French factory_major converted to a captor-owned factory_minor (`whenCapturedChangesInto`), and the airfield (`Capture Units On Entering Territory = true`, L6194). No bonus objective, no special trigger. Relative to Italy's 10-PU economy that is a large gain; relative to Germany's it is a transfer, not a creation, of value.

Politics: Germany and Italy start at War with Britain, UK_Pacific, ANZAC and France (e.g. L5902) and at Neutrality with Russia and the USA; USA/USSR enter by political action or scripted triggers.

## 11. Compatibility constraints that bind any extension

- **Save games**: never rename/delete private fields or move packages of `GameDataComponent` subclasses (`game-app/game-core/AGENTS.md`); `MustFightBattle` is serialized inside saves and its `BattleStep` `Order` enum must not be reordered (`GC/triplea/delegate/battle/AGENTS.md`).
- **Network**: never change a signature or reuse a code on any `@RemoteActionCode` method (`GC/engine/message/RemoteActionCode.java`; enforced by `game-app/game-core/src/test/java/games/strategy/engine/message/RemoteActionCodeTest.java` against `required-op-codes.csv`, 230 rows). Affected interfaces include `Player` and all `GC/triplea/delegate/remote/I*Delegate` interfaces.
- **Style**: Google Java Format via Spotless, PMD, AssertJ in tests, Lombok, `Optional` over null, no boolean parameters, step-down ordering (`AGENTS.md`).
- **New subprojects** apply the `triplea-java-library` convention plugin (`gradle/build-logic/AGENTS.md`) and are registered in `settings.gradle.kts`.

## 12. What does not exist (and would have to be built)

1. A legal-move / legal-action enumerator (§8).
2. Any JSON or text export of game state (§4).
3. Seeded or scripted dice for the battle calculators (§5); a seed hook exists only at the `ServerGame` level.
4. A rules-faithful multi-battle or whole-turn simulator: `ProSimulateTurnUtils` applies averaged outcomes and ignores scramble, raids, air battles.
5. Any out-of-process API: communication is Java serialization and `@RemoteActionCode` messaging only.
6. A headless game host that is not the lobby bot (`GameTestUtils` is test code, and depends on Mockito to construct `HeadlessLaunchAction`).
7. Any evaluation function beyond TUV and `ProTerritoryValueUtils`.
8. Handling of the `UserActions` step by any AI.
